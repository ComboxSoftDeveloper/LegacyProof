# LegacyProof

Замеры и проверки к статье «А чё, так можно было? Три места в .NET, которые
не развидеть» — решения, принятые давно и уже не отменяемые, и их цена
для кода, который пишется сегодня.

BenchmarkDotNet 0.15.8, Release, .NET 8, .NET 9 и .NET 10 в одном запуске,
со снятием машинного кода.

Статья: [«А чё, так можно было? Три места в .NET, которые не развидеть»](https://habr.com/ru/articles/1082672/)

## Что проверяется

| Раздел | Что смотрим | Что сравнивается |
| --- | --- | --- |
| 1 | пустой наследник | `Random` против класса, который от него унаследован и пуст |
| 2 | проверка типа массива | создание `Span` по массиву ссылочного и значимого типа |
| 3 | матрицы | умножение и сложение, размеры и раскладка типов |
| отчёт `inherit` | какая реализация досталась | четыре способа создать генератор |
| отчёт `covariance` | где срабатывает проверка | запись в массив и создание `Span` |
| отчёт `matrices` | как объявлены типы | размеры, число полей, вложенные типы |

## Результаты

### Какая реализация досталась наследнику

```
  как создан                     реализация

  new Random()                    XoshiroImpl
  new EmptyRandom()               Net5CompatDerivedImpl
  new Random(42)                  Net5CompatSeedImpl
  new SeededRandom(42)            Net5CompatDerivedImpl

Первые 5 чисел с начальным значением 42:

  Random               668   140   125   522   168
  SeededRandom         668   140   125   522   168
```

Наследник ничего не переопределяет, но получает другую реализацию. Числа
при этом те же: отличается путь вызова.

### Базовый тип против пустого наследника

| Метод | i9-10900KF | Ryzen 9 5950X | Xeon W-2255 | Xeon Silver 4314 |
| --- | --- | --- | --- | --- |
| `Next` | 1,816 / 2,608 | 2,333 / 3,190 | 2,318 / 3,138 | 3,196 / 4,104 |
| `NextDouble` | 2,618 / 3,937 | 3,104 / 4,434 | 2,020 / 4,940 | 3,316 / 6,034 |
| `NextBytes`, 256 байт | 37,025 / 537,487 | 35,885 / 572,608 | 50,093 / 648,626 | 51,063 / 889,873 |

Наносекунды, базовый тип и пустой наследник, .NET 10. На `Next` наследник
отстаёт в 1,28–1,44 раза, на заполнении буфера — в 12,95–17,43 раза.

Разница на буфере самая большая: `Net5CompatDerivedImpl` пишет по одному
байту за раз, а `XoshiroImpl` — сразу по восемь.

### Массив, который не того типа

```
  objects.GetType()              String[]
  ReferenceEquals(strings, objects)  True

  objects[0] = "строка"           прошло
  objects[0] = 42                 ArrayTypeMismatchException
  new Span<object>(objects)       ArrayTypeMismatchException
  new Span<string>(strings)       прошло
```

`string[]` и `object[]` тут один и тот же объект: `ReferenceEquals` возвращает
`true`, а тип остаётся `String[]`.

### Создание Span

| Массив | i9-10900KF | Ryzen 9 5950X | Xeon W-2255 | Xeon Silver 4314 |
| --- | --- | --- | --- | --- |
| `int[]` | 0,4034 | 0,2886 | 0,4684 | 0,6912 |
| `string[]` | 0,3966 | 0,2679 | 0,4671 | 0,7177 |

Наносекунды, .NET 10. Проверка типа массива в замере себя не проявила: она
в коде есть, но джит её выбрасывает, когда тип массива известен в точке
вызова.

### Как объявлены матрицы

```
  тип            размер   открытых полей   все поля float

  Matrix4x4        64 байт              16              да
  Matrix3x2        24 байт               6              да
  Vector4          16 байт               4              да

Вложенные непубличные типы у Matrix4x4:

  Impl
```

### Действия над матрицами

| Действие | i9-10900KF | Ryzen 9 5950X | Xeon W-2255 | Xeon Silver 4314 |
| --- | --- | --- | --- | --- |
| умножение 4×4 | 6,306 | 6,405 | 7,081 | 11,601 |
| сложение 4×4 | 2,353 | 4,464 | 3,044 | 10,795 |
| умножение 3×2 | 4,921 | 6,184 | 3,912 | 6,101 |

Наносекунды, .NET 10. Второй реализации `Matrix4x4` в .NET нет, поэтому
сравнивать эти числа не с чем. Четыре колонки показывают разброс по железу.

## Как воспроизвести

Нужны SDK .NET 8, 9 и 10: BenchmarkDotNet поднимает по процессу на рантайм.

```
dotnet --list-sdks
```

В пути к проекту не должно быть запятых и точек с запятой. BenchmarkDotNet
собирает вспомогательный проект и передаёт путь в MSBuild без кавычек, тот
разбирает эти знаки как разделители списка свойств и падает с MSB1006.
Батник проверяет путь и останавливается сразу.

Весь прогон одной командой:

```
all.bat
```

Замеры идут тремя отдельными запусками, по классу на запуск: отчёт пишется
сразу после каждого, и обрыв в середине не съедает сделанное.

Вручную, без скрипта:

```
dotnet run -c Release -f net10.0 -- checks
dotnet run -c Release -f net10.0 -- inherit
dotnet run -c Release -f net10.0 -- covariance
dotnet run -c Release -f net10.0 -- matrices
dotnet run -c Release -f net10.0 -- --filter *InheritBench*
dotnet run -c Release -f net10.0 -- --filter *SpanBench*
dotnet run -c Release -f net10.0 -- --filter *MatrixBench*
```

Аргумент `noasm` выключает снятие машинного кода.

Причина любого сбоя записывается в `Bdn\LegacyProof.log`.

## Как устроен замер

Все измеряемые методы собраны в `Subjects.cs`, у каждого `NoInlining`.

Наследник `EmptyRandom` объявлен пустым: ни одного переопределённого метода,
ни одного поля. Сверка это подтверждает: у него нет ни одного объявленного
метода. `SeededRandom` отличается только тем, что передаёт начальное значение
базовому типу.

В разделе про `Span` замеряется именно создание, работа с содержимым туда
не входит. Массивы одного размера, различается только тип элемента.

Отчёты читают поле `_impl` и объявления типов отражением. Имена заданы
строками, поэтому смена реализации сломает чтение, и сверка это заметит.

## Что проверялось и чем

| Что проверялось | Чем |
| --- | --- |
| Пустому наследнику достаётся другая реализация | отчёт `checks` читает поле `_impl` у обоих |
| Наследник действительно пустой | отчёт `checks` считает объявленные методы отражением |
| Числа у наследника те же | отчёт `checks` сравнивает 1000 значений |
| Массив строк присваивается в массив объектов | отчёт `checks` сравнивает ссылки |
| Запись значения другого типа не проходит | отчёт `checks` ловит исключение |
| `Span` проверяет тип массива при создании | отчёт `checks` пробует оба случая |
| Матрица объявлена так, как описано | отчёт `checks` считает поля и вложенные типы |
| Дело не в сборщике мусора | режим `DOTNET_gcServer=1` |
| Дело не в конкретной машине | четыре машины, выгрузки всех четырёх в `Results` |
| Дело не в конкретной версии | .NET 8, 9 и 10 в одном запуске |

Все замеры сняты на x64 под Windows.

Дизассемблер на Linux требует установленного `perf`. Выключается аргументом
`noasm`.

## Границы

Числа в этом файле берутся только из отчётов.

Проект показывает цену решений, а не предлагает их менять. Проверка
собственного типа в `Random`, проверка типа массива в `Span` и объявление
матриц сделаны намеренно: без них сломался бы уже написанный код.

Ссылки на исходники .NET даны на тег `v10.0.0`, коммит зафиксирован: `main`
уедет, и номера строк перестанут совпадать.
